## Que es el Lazy Loading:
- Angular devuelve **toda la pagina** al ser un SPA, pero con el *Lazy Loading*, el no procesa estos modulos o componnetes hasta que el usuario ingrese a ellos.


### Cuando se debe aplicar el Lazy Loading?
- **Aplicaciones grandes o medianas**
    - Si tu SPA tiene muchos módulos, páginas o funcionalidades, cargar todo al inicio puede hacer que la app tarde mucho en arrancar.
    - Lazy-loading permite cargar solo lo necesario al inicio y el resto bajo demanda.
- **Módulos que no se usan inmediatamente**
    - Por ejemplo: panel de administración, perfil del usuario, reportes avanzados, dashboards complejos.
    - Si el usuario no entra a estas secciones al abrir la app, no tiene sentido cargarlas de golpe.
- **Funcionalidades poco frecuentes o secundarias**
    - Módulos que los usuarios visitan raramente o que no son críticos para la primera interacción.
    - Ejemplo: configuración avanzada, historial de transacciones, estadísticas complejas.
- **Rutas que se pueden dividir claramente**
    - Lazy-loading funciona mejor si puedes separar tu aplicación en **módulos independientes**, con rutas propias y componentes agrupados.


### Aplicar Lazy Loading:
- **Cargar un Lazy Component**
	```ts
	// ❗ Nuestro componente tiene que tener export default
	export default class DashboardPageComponent {}
	
	
	
	// ✅ Para cargarlo en nuestras rutas solo hacer un import apuntando hacia el componente
	const routes: Routes = [
	
	  {
	    path: "",
	    loadComponent: () => import("./features/dashboard/pages/dashboard-page/dashboard-page.component")
	  }
	
	];
	
	```

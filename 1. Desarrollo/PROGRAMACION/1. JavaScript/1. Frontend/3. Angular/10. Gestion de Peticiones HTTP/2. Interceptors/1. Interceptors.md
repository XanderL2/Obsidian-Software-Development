## Que son los interceptors:
- Son estructuras que interceptan tanto el *request como el response de cada solicitud* http que se hace con el HttpClient.
- Esta nos puede servir para:
	- Agregar un token en los headers.
	- Manejar errores globalmente y no tener que manejarlos en cada peticion.
	- Agregar loaders globales (No especificos).
	- Mostar toasts (Mensajes de error globales).

### Ejemplo:
- El `{ts icon} req` hace referencia al *objeto request que esta a punto de salir* de la app.
- EL `{ts icon} next` es la *funcion que se debe llamar para que la peticion continue con su camino*, ya sea al backend o al siguiente interceptor.
- El `{ts icon}next` *devuelve* un observable que *representa la response* del servidor y otros *eventos relacionados*

```ts
import { HttpErrorResponse, HttpInterceptorFn } from '@angular/common/http';
import { catchError, throwError } from 'rxjs';


export const logginInterceptor: HttpInterceptorFn = (req, next) => {

  // Log de la request (entrada)
  console.log('Request:', req);

  const token = localStorage.getItem('token');

  if (token) {
    const newRequest = req.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`
      }
    });
  } 

  // next(req) envía la request y retorna un observable de la response
  return next(req).pipe(
    tap({
      next: (event) => {
        // Log de la response (salida)
        if (event.type === HttpEventType.Response) {
			console.log(req.url, 'returned a response with status', event.status);
        }
      }
    })
  ); 
};
```

```ts title:app.config.ts
export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }), 
    provideRouter(routes),
    provideHttpClient(withInterceptors(
      [loadingInterceptor] // 👈 Aqui usamos nuestros interceptors
    ))

  ]
};
```

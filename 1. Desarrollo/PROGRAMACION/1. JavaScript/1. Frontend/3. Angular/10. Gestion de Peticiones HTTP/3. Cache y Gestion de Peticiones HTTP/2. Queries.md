## Que es una Query:
- Una query es un objeto que *representa una petición al backend + su estado y cache*.
- Tiene el mismo comportamiento que rxResource, osea que si cambia una queryKey, se realiza de nuevo la peticion.
### Ejemplo Basico:

- *Query Key:* Es el identificador unico del cache de la peticion
- *QueryFn:* Es la propia peticion http en si, envuelta en una promesa.
```ts
productsQuery = injectQuery(() => ({
  queryKey: ['products'], // Identificador unico de los datos
  queryFn: () => api.getProducts(), // función que obtiene los datos del backend
}));
```

---
> ⚠️ *El query key no identifica la peticion, sino los datos, por ejemplo:*
```ts
['products'] // 👈 Representa el cache de todos los productos
['products', { page: 1 }] // 👈 Representa el cache de la pagina 1 de productos
['products', productId]  // 👈 Representa el cache de los detalles de 1 produtcto
```

### Estados de la peticion (Loading, success y error):

- **Cuando la peticion se esta realizando `{ts icon} isLoading()`**
	```html
	@if (productsQuery.isLoading()) {
	  <app-skeleton />
	}
	```

- **Cuando la peticion fue correcta `{ts icon} isSuccess()`**
	```html
	@if (productsQuery.isSuccess()) {
	  <ProductsList [products]="productsQuery.data()" />
	}
	```
	
- **Cuando la peticion dio error `{ts icon} isError()`**
	```html
	@if (productsQuery.isError()) {
	  <p>Error al cargar productos</p>
	}

	```

### Controlar cuando se debe disparar la peticion:

- *Enable:* 
	- Es un parametro que controla cuando se debe lanzar la peticion HTTP.
	- Por defecto esta en True, asi que se lanza apenas se inicializa el servicio. 
	- Pero si no queremos que se lance apenas se inicializa el servicio, o queremos hacerlo bajo una condicion debemos modificar este parametro.
```ts
// Por ejemplo, si queremos que lance la peticion solo si existe un Id
productsQuery = injectQuery(() => ({
  queryKey: ['products', this.id()], 
  queryFn: () => api.getProducts(), 
  enable: this.id() !== null
}));
```
